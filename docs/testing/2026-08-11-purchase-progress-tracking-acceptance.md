# 采购进度追踪 Agent 验收记录

日期：2026-08-11

## 验收范围

- 从中控已保存的采购申请记录开始追踪，不接收浏览器传入的内部关联对象。
- 普通 LangChain Agent 使用 MES 白名单内的只读 Tool 查询采购订单、收货和入库。
- 独立验证智能体根据真实 StepResult 区分完成、业务待推进、证据不足和技术失败。
- 不调用新增、修改、审核、删除等写操作。

## 自动化验证

- 假 MES 纵向闭环覆盖：采购申请编号关联采购订单，订单编号继续关联收货记录。
- 无采购订单时返回 `business_pending`，而不是技术失败。
- Tool Loop 与结构化总结分离，适配当前模型的 ProviderStrategy。
- 相同只读 Tool 与相同参数只执行一次；并发 Tool 调用的 step ID 保持唯一。
- Tool Loop 达到递归预算后，将已收集证据交给总结和验证智能体，不直接编造结论。

## 真实 MES 只读验收

连接状态：成功。

可用采购追踪 Tool：采购申请、采购订单、订单明细、收货记录、入库单和入库明细，共 8 个只读 API Tool。

一次真实追踪结果：

- 采购订单：1 条。
- 收货记录：0 条。
- 入库记录：0 条。
- 最终状态：`business_pending`。
- 实际 Tool 请求：8 次，全部成功。
- 写操作：0 次。

该结果表示技术链路已经完成，所选采购业务当前尚未推进到收货和入库阶段。

## 已知限制

- 当前模型一次真实追踪约需两分钟，后续需要通过动态 Tool 缩减和上下文压缩优化时延。
- 本地测试业务系统未启动时会输出降级告警，但不影响已连接的真实 MES 只读追踪。
- 当前只开放采购进度追踪所需的部分 API，不代表已经理解或开放 MES 全部接口。
