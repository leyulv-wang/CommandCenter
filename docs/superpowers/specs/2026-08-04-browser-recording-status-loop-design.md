# 浏览器扩展录制状态闭环设计

## 1. 目标

完成真实 MES 只读演示的最小纵向闭环：

1. 员工在浏览器扩展中开始录制；
2. 扩展采集脱敏后的页面事件和网络事件；
3. 中控接收并验证证据；
4. 智能体分析演示并生成候选 Skill；
5. 中控执行只读验证；
6. 用户能在中控页面确认最终成功或失败。

页面展示只服务于确认闭环状态，不建设完整管理后台或复杂审计界面。

## 2. 设计原则

- 智能体继续负责演示理解、Tool 对齐、Skill 生成和测试结果判断。
- 确定性代码只负责协议校验、录制生命周期、凭证清理、安全错误输出和状态持久化。
- 不记录或展示 Token、Cookie、请求正文、响应正文、表单值等敏感内容。
- 验证失败必须形成终态，不能让录制永久停留在 `recording`。

## 3. 后端闭环

### 3.1 录制时间

新录制保存 `created_at` 和 `updated_at`。每次状态变化时更新 `updated_at`，用于识别最近一次录制。

### 3.2 证据验证失败

扩展事件入口仍使用 `ExtensionEventBatch` 严格校验，但由路由显式捕获验证失败：

- 先验证一次性录制令牌，避免未授权请求改变录制状态；
- 将录制状态更新为 `upload_failed`；
- 终止内存中的扩展录制会话；
- 清除该录制对应的临时凭证；
- 保存安全的错误摘要，仅包含字段位置、错误类型和通用说明；
- 返回结构化 `422`，不返回错误输入值。

### 3.3 成功状态

成功上传后沿用现有学习流程：

`recording → analyzing → verified_candidate`

智能体分析或只读验证未通过时进入明确失败终态，并保留安全的失败说明。

### 3.4 最近录制接口

增加只读列表接口，默认返回最近 10 条浏览器扩展录制。列表只包含：

- 录制 ID；
- 演示目标；
- 来源系统；
- 当前状态；
- 创建和更新时间；
- 安全的失败说明。

接口不返回操作轨迹、原始证据、凭证或模型内部上下文。

## 4. 前端最小展示

现有“演示工作台”增加一个简单的“浏览器扩展录制结果”区域，只突出最近一次录制：

- 录制中；
- 上传失败；
- 智能体分析中；
- Skill 验证成功；
- Skill 验证失败。

页面加载时查询一次，并提供手动刷新按钮。第一版不增加后台轮询、筛选、分页、详情抽屉、证据查看器或独立菜单。

## 5. 浏览器扩展反馈

扩展停止录制后继续显示中控返回的最终状态。上传失败时显示“录制上传失败，请查看中控”，避免退回到看似正常的“未录制”状态。

## 6. 测试与验收

### 6.1 自动测试

- 非法证据字段产生 `upload_failed`，并且响应和日志不包含输入值；
- 无效录制令牌不能改变录制状态；
- 失败后内存会话和临时凭证被清除；
- 最近录制接口不返回轨迹和敏感字段；
- 前端能显示成功、失败和进行中状态；
- 扩展能显示上传失败以及 `verified_candidate`。

### 6.2 真实验收

在 `yifeng.dtsum.com` 只执行一次采购申请列表查询和一次已有详情查看，不执行任何新增、编辑、保存、提交、审核、完成、反审核、反完成或删除操作。

验收通过必须同时满足：

1. 扩展停止后没有上传错误；
2. 后端录制进入终态；
3. 中控页面显示该终态；
4. 候选 Skill 状态为 `verified_candidate`；
5. 录制证据和日志中不含凭证与业务原始值；
6. MES 没有产生任何写操作。

## 7. 本期不做

- 完整录制历史管理；
- 原始证据查看和人工审核；
- 多系统筛选与统计；
- 自动重试无效录制；
- 多次演示融合；
- 写操作 Skill。
