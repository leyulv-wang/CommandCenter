# 两类接口 AI 快速接入可视化演示 Spec

状态：已实现

## 1. 目标

通过两个独立业务系统页面，完整展示两类接口从“未接入”到“AI 配置接入”，再到业务数据双向流转的过程。

两个系统初始都未接入中控：

1. 采购业务系统：流程类接口。
2. 办公用品系统：独立 URL 类接口。

## 2. 两类接口

### 2.1 采购业务系统

使用流程类接口：

- 多种流程共用一个启动接口。
- 使用 `fdTemplateId` 区分采购表单。
- 具体业务字段放在 `formValues` 中。

### 2.2 办公用品系统

使用独立 URL 类接口：

- 使用办公用品系统自己的提交 URL。
- 请求包含 `docOperator` 和 `formValues`。
- 具体业务字段由该表单单独定义。

## 3. AI 配置页面

AI 配置页面提供两个演示样例按钮：

1. 流程类采购系统。
2. 独立 URL 类办公用品系统。

点击按钮只负责把对应接口说明填入文本框。点击“AI 生成配置草稿”后，系统真实调用 `.env.ai` 中配置的大模型。

AI 需要识别并生成：

- 接口类型
- 接口地址
- `fdTemplateId`（流程类）
- 表单字段及字段类型
- 必填规则
- 请求参数映射

保存配置后，对应业务系统自动变为已接入。

## 4. 外部业务系统页面

采购系统和办公用品系统分别提供独立页面，运行在各自的服务端口。

每个页面包含：

1. 当前接入状态。
2. 创建并派发任务。
3. 待办任务列表。
4. 已完成任务列表。
5. 中控提交的新申请记录。
6. 任务处理结果和完成时间。
7. 本系统的一键重置按钮。
8. 提供给 AI 的接口说明。

两个页面使用不同的名称和视觉风格，让演示者能够明确看出它们是独立业务系统。

## 5. 任务中心

任务中心入口始终显示。

当没有业务系统接入时，不展示采购系统或办公用品系统，只显示：

```text
暂无已接入业务系统
请先在 AI 生成配置中完成系统接入
```

接入一个系统后，任务中心只展示该系统的申请表单和任务；两个系统都接入后，再汇总展示两个系统的内容。

任务中心现有的发起申请、待办任务和已完成任务功能保持不变，本阶段不继续扩展。

## 6. 演示流程

### 6.1 流程类接口演示

```text
采购系统处于未接入状态
  -> 在采购系统页面创建任务
  -> 中控暂时看不到该任务
  -> AI 配置页选择“流程类采购系统”样例
  -> AI 生成并保存 workflow 配置
  -> 采购系统自动变为已接入
  -> 中控读取采购任务并提交处理结果
  -> 采购系统页面显示已完成和处理结果
```

### 6.2 独立 URL 类接口演示

```text
办公用品系统处于未接入状态
  -> 在办公用品系统页面创建任务
  -> 中控暂时看不到该任务
  -> AI 配置页选择“独立 URL 类办公用品系统”样例
  -> AI 生成并保存 custom_url 配置
  -> 办公用品系统自动变为已接入
  -> 中控读取办公用品任务并提交处理结果
  -> 办公用品系统页面显示已完成和处理结果
```

## 7. 重复演示

两个系统分别重置，互不影响，不提供“全部重置”。

单个系统重置后：

1. 删除该系统通过 AI 保存的申请配置。
2. 恢复为未接入状态。
3. 清空演示期间产生的申请和处理结果。
4. 恢复该系统的预置任务。
5. 保留内部任务处理表单。
6. 可以使用相同系统编码和表单编码再次演示。

## 8. 简单数据存储

两个业务系统分别使用独立 SQLite 数据库：

```text
采购业务系统    -> connected.sqlite3
办公用品系统    -> onboarding.sqlite3
```

每个数据库保留两类数据：

1. `tasks`：任务编号、标题、任务内容、处理人、状态、处理结果、创建时间和完成时间。
2. `submissions`：单据编号、操作人、表单内容、创建时间、接口类型和流程模板编号。

采购流程类单据记录 `fdTemplateId`；办公用品独立 URL 类不需要流程模板编号。

业务数据只保存在对应业务系统中。中控通过 API 查询和提交，不复制完整业务数据。中控只保存系统接入状态和表单配置。

重置某个系统时，只恢复该系统自己的 SQLite 数据、接入状态和 AI 表单配置，不影响另一个系统。

## 9. 第一版不做

- 登录和权限管理
- 新的任务中心功能
- 业务审批流程设计器
- AI 自动处理任务
- 真实客户环境调用
- 多个采购或办公用品表单的复杂管理

## 10. 验收标准

1. 两个业务系统初始都显示未接入。
2. 任务中心在无系统接入时显示空状态，不显示具体系统。
3. AI 页面能快速载入两类接口说明样例。
4. 两类配置草稿均由真实大模型生成。
5. 采购系统生成 `workflow` 配置，并包含正确的 `fdTemplateId`。
6. 办公用品系统生成 `custom_url` 配置。
7. 保存配置后，对应系统自动接入并出现在任务中心。
8. 外部系统创建的任务能够进入中控。
9. 中控处理后，外部系统页面能够显示处理结果。
10. 中控发起的新申请能够显示在对应外部系统页面。
11. 两个系统可以分别重置并重复演示。
12. 两个业务系统的数据分别保存在自己的 SQLite 数据库中。

## 11. 一句话总结

用两个真实可见的独立业务系统，证明中控能够通过 AI 快速接入流程类和独立 URL 类接口，并完成申请与任务处理的数据闭环。
