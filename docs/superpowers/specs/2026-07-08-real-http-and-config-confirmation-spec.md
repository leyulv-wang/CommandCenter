# 真实接口测试与快速接入测试 Spec

状态：已实现基础版本。

已实现内容：

1. AI 配置草稿可以保存为正式表单。
2. 表单提交页会展示新保存的表单。
3. 表单可以标记为“真实接口提交”或“模拟提交”。
4. 铁塔订单新增已配置为真实 HTTP 提交。
5. 采购、售后、人事等样例表单已配置为模拟提交。
6. 后端测试和前端构建已通过。

仍需现场确认：

1. 客户真实接口是否允许测试提交。
2. 客户真实接口是否需要鉴权。
3. 客户真实接口成功和失败时的返回格式。

## 1. 当前阶段目标

当前阶段要把项目从“原型可演示”推进到“可以验证真实接入能力”。

本阶段只做两件事：

1. 做一个已经接入外部系统的真实接口测试表单。
2. 做一个还没有接入外部系统的模拟表单，用来反复演示快速接入新表单的能力。

这两个场景分别回答两个问题：

```text
真实接口测试：系统能不能真正调用客户 API？
模拟表单测试：系统能不能快速接入一个新表单？
```

## 2. 已有基础

目前已经完成：

1. 后端表单配置能力。
2. 前端动态表单页面。
3. AI 根据接口说明生成配置草稿。
4. 表单字段校验。
5. 表单提交流程。
6. 模拟提交能力。

当前缺少的是：

1. 配置草稿保存为正式表单。
2. 真实外部接口提交。
3. 一个清晰的快速接入演示场景。

## 3. 核心概念

### 3.1 真实接口表单

真实接口表单用于验证系统是否能调用客户真实 API。

它的流程是：

```text
用户填写表单
  ↓
系统生成提交数据
  ↓
系统调用客户真实接口
  ↓
显示真实返回结果
```

### 3.2 模拟表单

模拟表单用于演示“新表单快速接入”。

它不会真的调用客户系统，而是调用本地模拟接口，返回一个假的成功结果。

它的流程是：

```text
AI 生成配置草稿
  ↓
管理员确认保存
  ↓
新表单出现在页面里
  ↓
用户填写表单
  ↓
系统模拟提交成功
```

模拟表单的作用是方便反复测试，不会污染真实业务数据。

## 4. 为什么需要模拟表单

真实系统一旦接入成功，后续就是正式接入状态。

如果每次都用真实系统测试“新表单接入流程”，会有几个问题：

1. 需要客户不断提供新接口。
2. 真实接口可能不能随便测试。
3. 测试数据可能污染客户系统。
4. 接口鉴权、网络、环境可能影响演示。

所以需要一个模拟表单场景。

模拟表单证明的是：

```text
从接口说明到可填写表单，这个流程可以快速跑通。
```

真实接口证明的是：

```text
我们的系统可以真正调用外部业务系统。
```

两个场景都需要，但验证的价值不同。

## 5. 本阶段要做的功能

### 5.1 保存 AI 配置草稿

AI 生成配置后，页面现在只展示草稿。

本阶段要增加：

```text
保存为正式表单
```

保存后，这个表单应该出现在“表单提交”页面中。

第一版规则：

1. 保存前需要管理员确认。
2. 如果表单编码已存在，提示错误。
3. 不自动覆盖已有表单。
4. AI 生成的配置不能绕过人工确认直接启用。

### 5.2 真实接口提交

当前提交是模拟结果。

本阶段要支持：

```text
真实 HTTP 提交
```

也就是系统可以把用户填写的内容真正发送到客户提供的 API。

第一版只需要做到：

1. 能调用真实 URL。
2. 能显示成功结果。
3. 能显示失败原因。
4. 真实接口不可用时，给出清楚提示。

### 5.3 表单提交页展示来源

表单提交页需要让人看得出当前表单是哪种类型：

```text
真实接口表单
模拟测试表单
```

这样演示时不会混淆。

## 6. 两个测试场景

### 6.1 真实接口测试：铁塔订单新增

用途：

```text
验证系统可以调用真实客户接口。
```

演示流程：

```text
选择铁塔订单新增
  ↓
填写订单号、合同编号、商品明细
  ↓
点击提交
  ↓
系统调用真实接口
  ↓
显示客户接口返回结果
```

需要确认：

1. 真实接口是否允许测试提交。
2. 是否需要鉴权。
3. 成功时返回什么。
4. 失败时返回什么。

### 6.2 快速接入测试：办公用品申请

用途：

```text
验证一个新表单可以通过 AI 和配置快速接入。
```

演示流程：

```text
在 AI 配置页输入办公用品申请的接口说明
  ↓
AI 生成配置草稿
  ↓
管理员查看字段和风险提示
  ↓
保存为正式表单
  ↓
表单提交页出现办公用品申请
  ↓
填写并提交
  ↓
系统返回模拟成功结果
```

建议字段：

1. 申请物品。
2. 数量。
3. 用途。
4. 申请人。

这个表单不需要真实外部系统，主要用于反复演示快速接入流程。

## 7. 本阶段不做

本阶段不做：

1. 员工自然语言找表单。
2. 员工自然语言自动填单。
3. 多轮追问。
4. 完整审批流。
5. 登录权限系统。
6. 数据大屏。
7. 完整业务系统功能。

## 8. 成功标准

本阶段完成后，需要能演示：

1. AI 生成的配置草稿可以保存为正式表单。
2. 保存后的表单会出现在表单提交页。
3. 办公用品申请可以作为模拟表单反复提交测试。
4. 铁塔订单新增可以作为真实接口表单测试真实提交。
5. 真实接口失败时，页面能显示清楚原因。
6. 演示时能清楚区分“真实接口表单”和“模拟测试表单”。

## 9. 一句话总结

本阶段要证明两件事：

```text
系统能真实接入外部 API。
系统也能用 AI + 配置快速接入一个新表单，并通过模拟提交反复测试。
```
