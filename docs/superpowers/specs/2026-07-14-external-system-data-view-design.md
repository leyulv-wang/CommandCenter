# 外部业务系统统一数据读取 Spec

状态：已实现

## 1. 目标

管理员在“外部业务系统”页面选择一个已接入系统后，中控通过该系统的 API 读取全部任务和全部申请数据，并以表格形式统一展示。

第一版不区分登录用户和数据权限，不传用户筛选条件。

## 2. 数据范围

每个已接入系统展示两类数据：

1. 任务数据：任务编号、标题、状态、处理人、创建时间、完成时间、任务内容和处理结果。
2. 申请数据：单据号、操作人、来源、接口类型、流程模板编号、创建时间和表单字段。

具体业务字段按照“字段名 / 内容”展示，不直接输出整段 JSON。

## 3. 读取方式

前端只访问中控接口，不直接访问外部系统。

```text
前端选择系统
  -> 中控校验系统已经接入
  -> 中控调用外部系统任务查询 API
  -> 中控调用外部系统申请查询 API
  -> 中控统一补充系统信息并返回
  -> 前端表格展示
```

外部系统任务查询 API 在不提供 `operator_id` 时返回全部任务；原有任务中心继续提供 `operator_id`，其行为不变。

## 4. 页面行为

1. 选择已接入系统后自动读取全部数据。
2. 页面提供“全部任务”和“全部申请”两个数据表格。
3. 状态、接口类型和数据来源使用标签展示。
4. 内容字段使用结构化键值列表展示。
5. “刷新数据”同时重新读取两个表格。
6. 未接入的接口说明样例不读取业务数据。
7. 外部系统不可用时显示明确错误，不使用伪造数据代替。

## 5. 第一版不做

- 登录和权限控制
- 按用户、部门或时间筛选
- 分页、导出和批量操作
- 跨系统数据合并表
- 自动推断任意数据库表结构

## 6. 验收标准

1. 中控具有按系统编码读取全部业务数据的统一接口。
2. 统一接口只允许读取已接入系统。
3. 读取操作确实通过外部系统 HTTP API 完成。
4. 不传用户编号时能够取得该系统全部任务。
5. 原任务中心按用户读取任务的功能不受影响。
6. 前端能够分别用表格展示全部任务和全部申请。
7. 动态业务字段不再显示为整段 JSON。
8. 外部系统异常时返回并显示清晰的读取失败信息。
