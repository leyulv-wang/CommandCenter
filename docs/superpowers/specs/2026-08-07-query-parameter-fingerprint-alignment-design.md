# 查询参数脱敏等值对齐设计

## 背景

真实 MES 查询录制已经捕获并匹配 `GET /jeecg-boot/purchase/apply/list`，但后台分析拒绝生成
Skill。页面输入证据包含值的 HMAC 指纹，后台 `webRequest` 兜底证据仅包含查询参数名称，
智能体无法证明页面输入与 `applyBy`、`businessDivision` 等参数之间的对应关系。

本设计补齐脱敏后的等值证据，不上传查询参数原值，也不通过 MES 字段名称或按钮关键词进行
硬编码匹配。

## 目标

1. 页面输入值与 API query 参数值能够通过相同录制密钥生成的 HMAC 指纹进行等值比较。
2. 智能体基于页面语义、时序和指纹等值关系判断字段映射。
3. 查询参数原值、Cookie、Token、请求头和响应正文不得进入中控证据。
4. 同一机制适用于普通 HTTP、HTTPS、MES 及其他业务系统。
5. 后台分析拒绝时向界面提供脱敏、可操作的真实原因，而不是只有通用失败文案。

## 证据模型

网络 exchange 在现有 `query_parameter_names` 之外增加查询参数值指纹集合。每个参数名对应
零个或多个 HMAC-SHA256 指纹，以支持重复查询参数。空值保留参数存在性但不生成值指纹。

指纹使用录制会话已有的 `fingerprint_key`，与页面 `value_fingerprint` 使用相同算法和格式。
扩展可以短暂读取当前请求 URL 来计算指纹，但 IndexedDB 上传证据和后端持久化记录只能保存
参数名及指纹，不能保存原始查询参数值。

后端 Pydantic schema 对参数名和指纹格式进行确定性校验。该校验属于协议与隐私边界，不负责
判断业务语义。

## 数据流

1. 扩展后台 `webRequest` 观察活动录制标签页中允许 origin 的请求。
2. 停止录制时，证据转换器解析 URL 查询参数并逐值计算 HMAC 指纹。
3. 上传前生成只含参数名、参数值指纹、方法、路径、状态码和耗时的 exchange。
4. 后端保存脱敏 exchange，并向字段映射智能体提供页面控件证据、页面值指纹、query 参数
   指纹和 Tool schema。
5. 智能体综合语义与等值证据提出映射；代码只校验引用存在、目标属于允许 Tool 和 schema。
6. 分页、排序、固定筛选条件是否成为 Skill 输入由智能体判断，不用关键词列表决定。

## 主通道与兜底通道

页面注入主通道存在 HTTP 请求时仍只使用主通道；主通道缺失时才使用后台 `webRequest`
兜底。两条通道经过同一个证据转换器，因此输出完全相同的 query 指纹协议，不引入
MES 专用分支。

## 失败处理与展示

结构化模型调用异常、schema 校验失败、字段证据不足和无害测试失败应继续保持不同阶段。
界面只显示经过长度限制和敏感信息过滤的失败摘要。原始模型响应、凭证及请求值不得返回。
已经保存的录制证据不得因分析失败而删除，以便后台重新分析。

## 测试

1. 证据转换单元测试：query 原值不出现在输出中，相同值产生相同 HMAC，不同值产生不同
   HMAC，重复参数得到多个指纹，空值不生成指纹。
2. schema 测试：仅接受合法参数名和 `hmac-sha256:<64 hex>` 指纹。
3. 字段映射智能体提示测试：明确要求使用语义、时序和指纹等值证据，不能仅凭名称猜测。
4. 录制集成测试：页面输入指纹能够与 API query 指纹相等。
5. 隐私回归：上传 payload、后端记录和日志均不包含演示查询原值。
6. 本地真实扩展端到端测试以及后端、前端全量回归继续通过。
7. 真实 MES 最终只执行采购申请列表查询；成功标准是生成并验证只读 API Skill，不产生写入。

## 非目标

- 不采集或转发浏览器 Cookie、Authorization、Token、请求头或响应正文。
- 不为 MES 的 `applyBy`、`businessDivision` 或查询按钮添加固定规则。
- 不在本次实现写操作录制、浏览器回放或登录凭证自动迁移。
