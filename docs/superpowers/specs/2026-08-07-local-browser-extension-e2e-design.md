# 本地采购系统浏览器扩展闭环验收设计

## 1. 目标

在接触真实 MES 前，使用项目已有的采购业务系统完成可重复、可由智能体后台执行的真实浏览器闭环验收：

1. 启动 CommandCenter 后端和本地采购业务系统；
2. 在独立的自动化 Chromium 用户目录中加载扩展正式构建产物；
3. 通过扩展开始一次录制；
4. 在采购业务页面执行只读查询操作并观察真实 API；
5. 通过扩展停止录制；
6. 验证页面动作和 API 证据已上传；
7. 等待录制进入成功或明确失败的终态；
8. 关闭并重新打开扩展界面，确认最近状态可以恢复。

通过该验收后，真实 MES 只承担最后一次环境兼容性验证，不再承担基础功能调试。

## 2. 范围

### 2.1 复用组件

- CommandCenter 后端：`http://127.0.0.1:8000`；
- 采购业务系统：`http://127.0.0.1:8101`；
- 浏览器扩展构建产物：`browser_extension/dist/chrome-mv3`；
- 采购业务系统现有页面、SQLite 种子数据和查询 API；
- 现有录制、证据转换、上传、学习和状态查询接口。

### 2.2 不做

- 不新建第三套模拟业务系统；
- 不测试新增、提交、审批或删除等写操作；
- 不使用用户日常 Edge 配置和登录态；
- 不把 Playwright 脚本变成产品运行时依赖；
- 不以固定业务关键词替代智能体的证据理解和 Skill 生成。

## 3. 技术方案

采用 Playwright 驱动带扩展的独立 Chromium 持久化上下文。测试运行器负责确定性的环境准备、浏览器操作和结果断言；智能体继续负责录制语义理解、Tool 对齐、Skill 生成及验证判断。

如果机器上没有 Playwright 自带 Chromium，测试运行器优先使用已安装的 Chromium 内核浏览器可执行文件；浏览器版本与启动能力不满足要求时给出明确的环境失败，不降级成不加载真实扩展的假测试。

为了避免测试依赖弹窗坐标，扩展提供仅在开发构建或测试标志下可用的自动化入口。该入口调用与弹窗相同的后台消息协议，不复制录制业务逻辑。正式构建默认关闭测试入口。

## 4. 数据流

```text
测试运行器
  -> 启动/检查 CommandCenter 与采购业务系统
  -> 构建并加载真实扩展
  -> 打开采购页面
  -> 通过扩展协议开始录制
  -> 刷新页面并执行一次只读查询
  -> 页面观察器记录 DOM 动作和 fetch/XHR
  -> 通过扩展协议停止录制
  -> 扩展上传脱敏证据
  -> CommandCenter 智能体分析并验证
  -> 测试运行器轮询终态并校验结果
  -> 重载扩展界面并校验状态恢复
```

## 5. 验收场景

### 5.1 主路径

1. 打开采购系统首页；
2. 开始目标为“查询采购申请”的录制；
3. 刷新已经打开的业务标签页，用于覆盖扩展安装后旧标签页的注入场景；
4. 选择或输入现有查询条件并触发查询；
5. 等待列表 API 返回；
6. 停止录制；
7. 断言本地轨迹至少包含一个页面动作和一个可归因网络事件；
8. 断言后端录制不再停留在 `recording`；
9. 断言最终进入成功终态，或在失败时返回可定位且不含敏感数据的错误；
10. 重新打开扩展状态界面，断言它显示最近一次结果而不是无条件回到“未录制”。

### 5.2 回归场景

- 已经打开的页面能够在开始录制后被主动连接，或者提示并自动刷新；
- 没有采集到可上传证据时，扩展显示明确失败并结束后端录制会话；
- 上传中或分析中关闭扩展界面，再打开时能恢复状态；
- 中控后端不可用时，本地证据保留并显示可重试状态；
- 测试结束后不会留下活动录制会话或修改采购数据。

## 6. 安全与隔离

- 使用独立临时浏览器用户目录，测试结束后删除；
- 只允许访问 `127.0.0.1:8000` 和 `127.0.0.1:8101`；
- 测试不读取或复用真实 MES Cookie、Token 和账号；
- 仍沿用扩展的脱敏、origin 白名单和 CommandCenter 录制令牌；
- 测试代码仅判断事件类型、路径模板、状态和数量，不保存表单原始值或响应正文；
- 失败时保留必要的 Playwright trace、控制台错误和安全状态摘要，便于后台诊断。

## 7. 测试分层

1. 扩展单元测试：验证注入、状态恢复及失败处理的独立行为；
2. 后端集成测试：验证证据上传、录制终止和状态转换；
3. 浏览器 E2E：加载真实扩展，连接真实本地采购页面与 API；
4. MES 验收：本地三层全部通过后，只执行一次真实 MES 只读兼容性验证。

## 8. 完成标准

只有同时满足下列条件，才允许邀请用户进行 MES 实测：

- 扩展测试、后端相关测试和浏览器 E2E 全部通过；
- E2E 证明确实加载了扩展构建产物，而非模拟扩展消息；
- 页面动作和网络 API 证据均非空；
- 后端录制进入明确终态，没有遗留 `recording` 会话；
- 扩展界面重开后能恢复最近结果；
- 采购系统种子数据在测试前后保持一致；
- 测试输出不包含凭证、Cookie、Token 或业务原始字段值。
