# Browser-BC API 录制器替换设计

日期：2026-08-07

## 1. 背景与目标

CommandCenter 当前的轻量浏览器扩展使用原生 JavaScript 和可选
`chrome.debugger` 权限观察网络请求。该实现已经验证了“员工演示一次，智能体学习并生成
API Skill”的方向，但录制能力、后台恢复、本地持久化和上传可靠性仍然较弱，并出现了
运行时权限申请失败。

本阶段直接采用 Browser-BC 的浏览器扩展作为新录制器底座，完整替换现有
`browser_extension/`。目标不是引入 Browser-BC 的完整产品，而是复用其成熟的浏览器证据
采集基础设施，接入 CommandCenter 已有的 FastAPI、LangGraph、多智能体学习、无害测试和
Skill 发布闭环。

本阶段只验收存在可靠 API 的路径。没有可靠 API 的录制可以被保存并标记为浏览器候选，
但浏览器执行和隔离验证不属于本次范围。

## 2. 决策

采用 Browser-BC 仓库 `5afc6d4` 提交中的 `extension/` 作为初始技术底座。

1. Browser-BC 扩展源码进入 CommandCenter 的 `browser_extension/`，替换现有原生扩展。
2. 保留 WXT、TypeScript、React、Dexie/IndexedDB 和现有测试结构。
3. 保留页面动作、DOM、表单、页面变化、导航、下载和网络证据采集。
4. 删除当前基于 `chrome.debugger` 的网络观察实现及其权限申请。
5. 不引入 Browser-BC 的本地 Python 服务、Claude Skill 安装器和控制面板。
6. 新建 CommandCenter 上传适配器，将 Browser-BC 轨迹转换并上传到现有录制 API。
7. Skill 的语义判断、API 归因、参数映射、验证和发布继续由 CommandCenter 智能体负责。

当前项目用于研究和内部原型验证，因此许可证不是本阶段的阻塞条件。源码中必须保留上游
来源、仓库地址和采用的提交号，方便追踪差异和后续同步。进入正式产品化前需要重新完成
许可证和商业使用评估。

## 3. 不采用的方案

### 3.1 Browser-BC 本地服务作为旁路服务

扩展先上传 Browser-BC 服务，再由旁路服务转发 CommandCenter。该方案可以减少扩展改动，
但会产生两套本地服务、两套状态和额外故障点，不符合当前纵向闭环优先的目标。

### 3.2 CommandCenter 原生兼容 Browser-BC 全部服务协议

让 CommandCenter 实现 Browser-BC 的 init、chunk、finalize、bucket 和 Skill 安装协议，会使
中控后端被外部项目的数据模型绑定，并重复现有学习与发布能力，因此不采用。

## 4. 架构边界

### 4.1 浏览器扩展

扩展只负责观察、脱敏、可靠保存和上传证据，不负责判断业务含义。

保留的模块边界：

- Content Script：记录用户动作、表单摘要、DOM 快照和页面变化。
- Injected Script：包装页面上下文中的 `fetch`、XHR、Beacon、WebSocket 和 EventSource。
- Background：管理录制状态、跨标签页事件、停止刷新和上传协调。
- IndexedDB：保存录制、事件、上传清单和失败恢复状态。
- Redactor：在证据离开浏览器前移除或摘要化密码、令牌、邮箱、电话等敏感信息。
- Upload Runner：按批次可靠上传，支持中断后继续。

扩展不得自行硬编码“某个按钮对应某个 API”。页面动作和网络请求只需共享同一录制、标签页
和时间轴证据。

### 4.2 CommandCenter 上传适配器

上传适配器位于扩展内部，是 Browser-BC 与 CommandCenter 之间唯一的协议耦合点。它负责：

1. 调用 `POST /recordings` 创建中控录制。
2. 调用 `POST /recordings/{id}/extension/start` 获取录制令牌。
3. 将 Journey 事件转换为 CommandCenter 的页面事件和网络交换证据。
4. 调用 `POST /recordings/{id}/extension/events` 分批上传。
5. 调用 `POST /recordings/{id}/extension/stop` 固定证据并触发异步学习。
6. 调用 `GET /recordings/{id}` 查询学习、测试和发布状态。

转换层只执行协议映射、长度限制和确定性校验。API 选择、字段语义、业务意图和 Skill 结构由
智能体判断，不能下沉为示例特定的代码规则。

### 4.3 CommandCenter 后端

继续使用现有闭环：

`证据持久化 -> 异步学习 -> API Tool 对齐 -> Skill 编译 -> 无害测试 -> 自动发布`

当轨迹包含多个 API 时，智能体结合操作顺序、页面语义、请求参数和值指纹判断哪些请求属于
演示目标。后端代码只允许白名单接口、校验 Schema、限制副作用并保存审计证据。

## 5. 数据流

1. 员工在扩展中输入或确认演示目标并开始录制。
2. 扩展创建 CommandCenter 录制会话，同时在 IndexedDB 建立本地轨迹。
3. 员工在 MES 或其他业务系统正常操作。
4. 页面动作、DOM 上下文和网络请求按发生时间写入同一条本地轨迹。
5. 扩展持续或分批上传已经脱敏的证据；网络临时失败不删除本地数据。
6. 员工停止录制，扩展先刷新待处理事件，再提交停止请求。
7. CommandCenter 返回 `202 Accepted`，后台智能体继续分析。
8. 扩展轮询录制状态，中控工作台显示学习、测试、发布或失败结果。
9. 发布后的 API Skill 可由用户在中控通过自然语言调用。

## 6. 配置与泛化

`yifeng.dtsum.com` 只是第一个站点配置，不得成为代码中的业务特例。

扩展配置至少包含：

- CommandCenter 服务地址；
- 允许录制的站点 origin 列表；
- `source_system`；
- 默认演示目标或由用户填写的演示目标；
- 是否采集网络请求体；
- 单个事件、批次和本地存储限制。

站点配置与通用录制引擎分离。新增业务系统应优先增加配置，而不是复制扩展或添加域名分支。

## 7. 安全与隐私边界

1. 密码、Cookie、Authorization、令牌、文件内容和原始剪贴板内容不得上传。
2. 网络请求体仅采集允许的文本类型，并执行长度限制和脱敏。
3. 默认只保留生成 API Skill 所需的证据。
4. 扩展页面脚本发来的事件视为不可信输入，必须经过类型和容量校验。
5. 录制令牌只用于单次录制，不写入 Skill。
6. 自动测试继续遵守现有只读或无害副作用边界。
7. 录制失败时保留本地证据和可理解的失败状态，不自动重放真实写操作。

## 8. 错误处理

- 中控不可达：录制保留在 IndexedDB，显示待上传并允许恢复。
- 页面刷新或扩展后台休眠：恢复活动录制和未上传事件。
- 单批证据被拒绝：记录安全的字段位置和错误类型，不显示敏感值。
- 网络事件无法与页面动作对齐：保留原始证据，交给智能体重新分析，不硬编码匹配结果。
- 学习模型失败：中控记录失败阶段和安全提示，允许重新分析，无需重新录制。
- 没有可靠 API：状态转为 `browser_candidate`，本阶段不自动浏览器回放。

## 9. 测试策略

### 9.1 扩展测试

- 页面动作、DOM、表单和网络事件采集；
- 敏感值脱敏和容量限制；
- IndexedDB 状态恢复；
- 分批上传、中断续传和停止刷新；
- Journey 事件到 CommandCenter 证据的协议转换；
- 不申请或使用 `chrome.debugger`；
- 站点配置不依赖 MES 特定业务字段。

### 9.2 后端测试

- 接受转换后的有效证据；
- 拒绝非法、越界或未授权证据；
- 页面操作与网络证据形成同一条 OperationTrace；
- 停止请求快速返回，后台学习继续运行；
- 可靠 API 轨迹生成并验证 API Skill；
- 缺少 API 证据时保存为浏览器候选。

### 9.3 纵向闭环验收

1. 加载替换后的扩展并开始录制，不再出现权限申请错误。
2. 在测试 MES 中完成一次不会影响原有数据的演示。
3. 中控收到页面与 API 证据，并显示异步处理状态。
4. 智能体生成候选 API Skill，完成无害测试并发布。
5. 用户用自然语言调用已发布 Skill，执行结果可在中控查看。

## 10. 本阶段完成定义

- 原轻量扩展已被 Browser-BC 技术底座替换；
- 不再存在 `chrome.debugger` 权限依赖；
- API 轨迹能够进入现有 CommandCenter 学习闭环；
- 配置、脱敏、恢复和上传具备自动化测试；
- 后端、前端和扩展完整测试通过；
- 浏览器执行闭环明确保留为下一阶段工作，不混入本次实现。
