# 跨系统联合录制与 Skill 沉淀设计

状态：待用户书面审核

日期：2026-08-13

适用范围：`D:\python\CommandCenter`

## 1. 背景

CommandCenter 已完成两条基础能力：一是浏览器扩展观察单个业务系统的页面动作和 API，并生成可复用 Skill；二是中控通过只读 API Tool 查询真实益丰 MES 的采购申请、采购订单、收货和入库信息。

下一阶段验证企业指挥中心的核心价值：员工演示一次跨系统工作，中控学习系统间的数据传递和操作顺序，沉淀为可验证、可复用的跨系统 Skill。第一版只实现两个系统的最小闭环，不扩展到桌面软件或无 API 系统。

## 2. 第一版业务场景

参与系统：

1. 真实益丰 MES：只读，用于查询并选择采购申请；
2. 本地采购业务系统：测试环境，允许创建、读取和删除采购跟进任务；
3. CommandCenter：负责联合录制、智能体学习、Skill 生成、自动验证和正式执行。

员工演示流程：

```text
开始联合录制
→ 在 MES 查询并查看一条采购申请
→ 查看申请中用户可见的采购明细
→ 切换到本地采购系统
→ 填写一个采购跟进任务及其多条物料明细
→ 提交任务
→ 结束联合录制
```

沉淀后的正式执行流程：

```text
用户自然语言查询 MES 采购申请
→ 中控展示候选记录
→ 用户选择一条可信记录
→ 用户要求“创建采购跟进任务”
→ 中控调用跨系统 Skill
→ 从 MES 只读获取所需信息
→ 在本地采购系统创建跟进任务
→ 返回 MES 申请与本地任务的关联结果
```

第一版不让智能体从多条候选采购申请中自行猜测用户指向的记录。

## 3. 目标

1. 扩展同时支持“单系统录制”和“联合录制”两个明确入口；
2. 一个联合录制会话可以观察两个已授权业务系统标签页；
3. 所有事件进入统一时间轴，并保留系统、标签页和 API Tool 归属；
4. 多智能体识别跨系统操作顺序、字段传递关系和成功结果；
5. 生成由多个系统 Tool 步骤组成的候选 Skill；
6. 自动验证时保持 MES 只读，仅在本地系统创建带测试标记的跟进任务；
7. 自动核对并删除测试任务；
8. 正式执行优先使用 API Tool，不回放员工页面点击；
9. 原有单系统录制、学习、验证和执行能力保持可用。

## 4. 非目标

- 不录制桌面应用；
- 不实现无 API 系统的浏览器回放；
- 不开放 MES 写操作；
- 不允许联合录制观察未选择的普通网页；
- 不实现三个及以上系统的产品交互，但内部协议不得限制未来增加系统；
- 不实现多次演示融合；
- 不实现账号、团队和企业级 Skill 权限；
- 不自动从多条采购申请中选择一条；
- 不把浏览器 Cookie、Token 或其他凭证保存进 Skill；
- 不把 MES 或本地系统的专用 Schema 作为唯一内部 Skill 表示。

## 5. 方案选择

采用“一个录制会话绑定多个已授权标签页”的方案。

未采用的方案：

- 分别录制两个系统后再合并：时间关系和字段传递证据容易丢失；
- 只录制单标签页并要求在同一标签页跳转：不符合员工日常多标签页操作方式。

联合录制使用一个录制编号形成天然统一的事件时间轴。单系统与联合录制的入口分开，避免员工误解；后端使用同一套录制协议、证据存储、学习流程和 Skill 表示，避免形成两套架构。

## 6. 浏览器扩展设计

### 6.1 录制模式

扩展提供：

```text
单系统录制
联合录制
```

单系统录制只观察用户开始录制时选中的业务标签页。

联合录制要求用户先选择参与系统。第一版固定为益丰 MES 和本地采购业务系统。扩展只允许符合已选系统精确 origin 的标签页加入会话；用户切换到其他网页时不采集页面内容和网络证据。

### 6.2 标签页加入会话

联合录制开始后：

1. 当前符合允许系统配置的标签页立即加入会话；
2. 用户激活另一个已选系统标签页时，该标签页加入同一会话；
3. 每个标签页拥有会话内稳定的标签页标识；
4. 标签页导航离开允许 origin 时暂停采集；
5. 标签页返回允许 origin 后可以继续采集；
6. 录制结束后解除全部标签页绑定。

### 6.3 事件上下文

所有页面与网络事件至少携带：

- `recording_id`；
- `recording_mode`：`single_system` 或 `multi_system`；
- `system_code`；
- 会话内 `tab_id`；
- 事件序号和时间；
- 页面 URL 与页面区域；
- 页面动作或状态变化；
- 请求与响应的脱敏摘要；
- 匹配的 API Tool 及证据引用。

标签页切换只用于恢复事件顺序和业务阶段，不能单独证明数据因果关系。

## 7. 本地采购跟进任务

本地采购系统增加独立的“采购跟进任务”，不复制或冒充 MES 原始采购申请。一份采购申请对应一个跟进任务，任务内可以包含多条物料明细。第一版字段：

- 任务名称和备注；
- 明细中的物料编码、数量、单位、建议供应商、需求时间和备注；
- 记录用途：正式或自动测试；
- 后台来源引用：录制编号、正式 Skill 执行编号或 MES 内部记录标识。

后台来源引用不出现在员工演示表单中。员工不需要知道、复制或填写 MES 申请编号和内部 ID。

提供创建、读取和删除 API。创建接口必须支持幂等键，防止模型超时或网络重试产生重复任务。删除能力只用于测试系统自动清理，并通过明确的测试任务标识限制作用范围。

## 8. 多智能体学习流程

### 8.1 轨迹整理智能体

根据统一时间轴、系统、标签页、页面区域和 API 证据，把演示整理成：

1. MES 查询及选择采购申请；
2. 获取采购申请主表和明细信息；
3. 切换本地采购系统；
4. 填写并提交采购跟进任务；
5. 确认创建结果。

该智能体识别业务片段，不决定具体字段映射。

### 8.2 API 归因智能体

分别判断每个业务片段对应的 API Tool，结合页面动作、请求参数、响应内容、OpenAPI 语义和页面状态变化，排除静态资源、字典加载、日志上报等伴随请求。一次页面动作可以对应多个 API。

### 8.3 跨系统字段映射智能体

结合页面标签、实际值、API 字段、格式转换和业务语义提出跨系统绑定，例如：

```text
MES.details[].articleNo          → local.items[].material_code
MES.details[].quantity           → local.items[].quantity
MES.details[].unit               → local.items[].unit
MES.details[].suggestedSupplier  → local.items[].suggested_supplier
MES.details[].requiredDate       → local.items[].required_date
```

这只是候选映射示例，不作为硬编码字段规则。真实映射必须引用录制事件、Tool 请求、Tool 响应和接口定义。时间相邻仅作为候选证据；值一致、业务标签和接口语义共同构成映射依据。无法确定时进入“需要重新演示”，不得猜测。

### 8.4 Skill 编译智能体

编译得到系统无关的跨系统 Skill：

1. 接收用户选中的可信 MES 采购申请；
2. 使用 MES 只读 Tool 获取所需主表和明细数据；
3. 将上一步输出绑定到本地采购跟进 Tool；
4. 创建本地跟进任务；
5. 回读并验证创建结果；
6. 返回两个系统的关联编号和执行摘要。

Skill 保存 Tool 引用、输入来源、跨步骤输出绑定、验证条件、幂等语义和权限要求，不保存凭证和页面坐标。

### 8.5 验证智能体

验证智能体根据真实 Tool 证据判断字段映射和执行结果。代码只强制执行安全边界、测试标记、幂等、资源限制和清理范围，不用样例字段分支替代智能体判断。

## 9. 自动验证与清理

```text
选择一条 MES 测试申请
→ 只读获取申请及明细
→ 在本地系统创建带“自动测试”标记的跟进任务
→ 回读创建结果
→ 验证关键字段和来源关系
→ 删除测试任务
→ 确认删除成功
→ 标记 Skill 已验证
```

规则：

- MES 始终只读；
- 本地测试任务必须带自动测试标记和验证运行编号；
- 只允许删除当前验证运行创建的测试任务；
- 字段核对完成后执行删除；
- 删除失败时保留记录、报告残留任务编号，并把清理状态标为失败；
- 不把删除失败伪装成完整验证成功；
- 分析或验证失败时保留脱敏录制证据，允许重新分析；
- 正式执行产生的跟进任务不得被自动清理。

## 10. 正式执行

用户先通过自然语言查询 MES 采购申请。中控展示候选结果，用户明确选择一条可信记录，然后要求创建采购跟进任务。

执行智能体负责：

- 理解用户目标；
- 选择跨系统 Skill；
- 根据当前 MES 证据补充必要只读查询；
- 执行字段绑定；
- 调用本地创建 Tool；
- 解释部分失败或业务数据缺失。

确定性代码负责：

- 防止前端注入未出现在可信查询结果中的 MES 内部编号；
- MES Tool 只读白名单；
- 本地写 Tool 的权限和 Schema；
- 正式执行与自动测试模式隔离；
- 幂等键；
- 调用次数、超时、响应大小和重试限制；
- 脱敏证据及审计记录。

实际复现优先调用 API Tool，不重新播放页面动作。页面录制用于教授业务流程、字段语义和系统间数据传递。

## 11. 失败处理

- 没有捕获到任一系统的核心 API：候选 Skill 不进入验证，提示缺少的系统证据；
- 只录到一个系统：保留录制，但不能生成跨系统 Skill；
- 字段映射不确定：进入需要重新演示，并指出需要补充的字段动作；
- MES 暂时不可用：不创建本地任务，保留录制和错误证据；
- 本地创建失败：不重试未确认幂等的写操作；
- 创建成功但回读失败：保留任务编号并报告验证不完整；
- 清理失败：报告残留测试任务，禁止自动删除正式数据；
- 用户切换到未授权网页：暂停该标签页采集，联合会话继续等待允许系统事件。

## 12. 界面范围

第一版只要求功能明确，不追求正式产品样式。

浏览器扩展展示：

- 单系统录制与联合录制入口；
- 已选择的业务系统；
- 已加入会话的系统和标签页；
- 录制状态；
- 分析、验证、清理和 Skill 生成结果。

中控展示：

- 最近联合录制；
- 两个系统是否都有有效证据；
- 识别出的跨系统字段绑定摘要；
- Skill 生成及自动验证状态；
- 自动测试任务是否已清理；
- 正式执行结果和两个系统的关联编号。

## 13. 测试策略

1. 协议单元测试：模式、系统、标签页、事件顺序和证据引用；
2. 扩展测试：只采集已选系统，多标签页事件进入同一会话，未授权网页不采集；
3. 后端集成测试：双系统事件合并、API 归因、字段绑定、Skill 编译；
4. 假数据纵向测试：MES 只读 fixture 与本地采购系统创建、回读、清理；
5. 失败测试：缺少系统证据、字段冲突、创建超时、重复请求、清理失败；
6. 真实手工演示：员工在真实 MES 和本地采购系统完成一次联合录制；
7. 自动验证：创建测试跟进任务、核对、删除并确认不存在；
8. 正式复现：用户查询并选择采购申请后，通过自然语言创建一条保留的正式跟进任务；
9. 回归测试：原有单系统录制、采购查询、详情及进度追踪保持可用。

## 14. 第一版验收标准

1. 扩展能明确选择单系统或联合录制；
2. 一个联合会话能记录 MES 和本地采购系统两个标签页；
3. 未选择的普通网页不会进入录制轨迹；
4. 智能体能识别两个系统、操作顺序和至少四项跨系统字段绑定；
5. 能生成包含两个系统 Tool 步骤的候选 Skill；
6. MES 自动验证期间没有任何写操作；
7. 本地系统能创建、回读并删除带自动测试标记的任务；
8. 清理结果可见且可审计；
9. 用户选择 MES 采购申请后，可以自然语言执行跨系统 Skill；
10. 正式执行后，本地系统存在字段正确的采购跟进任务；
11. 重复提交相同正式请求不会创建重复任务；
12. 原有单系统录制和已有 Tool/Skill 功能继续工作。

## 15. 后续演进

完成第一版后，再逐步考虑：

- 三个及以上系统的联合录制；
- 多次演示融合与不同用户的个性化 Skill；
- 当通用 Tool 不足时主动建议录制 Skill；
- 无 API 系统的浏览器操作 Tool；
- 桌面应用和 RPA 执行器；
- 账号、租户、团队和企业 Skill 权限；
- 风险分级、人工审批和生产写操作策略。
