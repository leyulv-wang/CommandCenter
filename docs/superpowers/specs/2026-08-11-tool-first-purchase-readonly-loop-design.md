# Tool 优先的采购申请只读闭环设计

## 1. 背景

当前项目通过浏览器演示学习了“查询采购申请列表”和“按请购人查询采购申请列表”两个候选 Skill。复盘后确认，两者实际调用同一个采购申请列表 API，只是参数不同。若把每种筛选条件都保存为 Skill，Skill 数量会快速膨胀，并重复表达业务系统本身已经提供的原子能力。

项目调整为“Tool 优先、Skill 补充”：先理解业务系统能够提供的 API 能力，再由智能体按任务检索和调用 Tool；Skill 只表达无法由单个通用 Tool 直接描述的特殊工作方法。

## 2. 关键概念

### 2.1 系统能力索引

系统能力索引描述一个业务系统有哪些业务域、资源和 API 操作。它可以读取完整 OpenAPI/Swagger 文档，但不代表所有接口都立即获得执行权限。

当前益丰 MES 文档包含大量接口。第一版只索引并执行采购申请领域中已经核验的少量只读接口，不建设全系统能力地图。

### 2.2 Tool

Tool 是业务系统提供的原子操作，例如：

- 查询采购申请列表；
- 按内部 ID 查询采购申请主记录；
- 按主记录 ID 查询采购申请明细。

筛选条件、分页和字段值是 Tool 参数，不产生新的 Skill。智能体负责理解自然语言、检索候选 Tool、提取参数并决定调用方式；确定性代码负责权限、参数协议、只读边界、超时和响应限制。

### 2.3 API 调用记录与学习证据

系统应自动记录允许范围内的 API 调用证据，用于持续学习：

- 用户表达与所选 Tool 的对应关系；
- 页面字段与 API 参数的对应关系；
- 参数样例和返回结构；
- Tool 调用是否成功；
- 可脱敏保存的业务语义与执行轨迹。

这些记录是 Tool 语义、使用样例和智能体学习材料，不自动成为 Skill。自动沉淀 API 调用记录与控制 Skill 数量并不冲突。

### 2.4 Skill

Skill 是特殊工作方法的可复用表达，适用于：

- 多个 Tool 需要按特定顺序协作；
- 存在岗位或用户特有的处理习惯；
- 需要跨系统搬运、核对或补充信息；
- API 无法完成，只能使用浏览器操作；
- 复杂流程反复出现，值得固化。

单个 API 调用、筛选条件变化、分页变化和一次性操作不应生成 Skill。

未来用户可以主动录制自定义 Skill；当通用 Tool 无法完成任务时，智能体也可以建议录制，但不能未经用户确认自动开始录制。个人、团队和企业 Skill 的权限区分留到账号体系之后设计。

## 3. 第一版范围

本轮只完成“采购申请只读 Tool 闭环”，不实现完整 MES 能力索引，也不实现用户自定义 Skill。

范围包括：

1. 查询采购申请列表；
2. 按请购人筛选列表；
3. 指定页码和每页条数；
4. 从查询结果选择一条记录；
5. 查看所选采购申请的主记录和申请明细；
6. 可视化展示列表与详情；
7. 自动记录 Tool 选择、参数、脱敏响应摘要和执行结果。

范围不包括：

- 新增、修改、提交、审批、删除等写操作；
- 全量处理 MES 的 3000 多个 API；
- 自动创建新的流程型 Skill；
- 个人、团队和企业 Skill 权限；
- 跨系统流程。

## 4. 用户流程

### 4.1 列表查询

1. 用户在中控输入自然语言任务。
2. 智能体识别为采购申请查询。
3. 智能体从采购申请领域检索列表 Tool。
4. 智能体提取 `applyBy`、`pageNo`、`pageSize` 等参数。
5. ToolExecutor 校验只读权限和参数协议并执行 MES API。
6. 中控以表格展示结果。
7. 系统保存本次调用的脱敏学习证据，不生成 Skill。

“查询采购申请列表”“查询孟明佳的采购申请”和“查询第二页、每页 10 条”均使用同一个列表 Tool。

### 4.2 查看详情

1. 用户在列表中点击“查看详情”。
2. 中控从所选行取得 MES 内部 ID，不要求用户查看或输入该 ID。
3. 智能体选择主记录详情 Tool，并在需要时继续调用申请明细 Tool。
4. 中控合并主记录与明细，以详情区域展示。
5. 系统分别记录每次 Tool 调用的证据，不生成 Skill。

第一版先支持从列表点击查看详情。通过自然语言表达“查看第一条详情”或“查看申请单号某某的详情”留作下一步增强。

## 5. 录制器职责

录制器继续自动观察页面动作和对应 API，用于补足 OpenAPI 文档缺失的业务语义，例如确认页面“请购人”字段对应 API 参数 `applyBy`。

录制完成后的学习结果应允许区分：

1. 新的 Tool 语义或参数映射；
2. 已知 Tool 的新使用样例；
3. 值得保存的流程型 Skill；
4. 证据不足，暂不沉淀。

当前闭环只使用前两类结果。Skill 判断和用户自定义录制在后续版本实现。

## 6. 错误处理

- 没有开放对应 Tool：提示当前采购领域未开放该能力，不临时生成 Skill。
- 缺少必要参数：由智能体请求补充，不猜测业务值。
- 查询返回多条：展示列表，由用户选择。
- 主记录存在但明细为空：展示主记录并标明暂无明细。
- 凭证失效：停止调用并提示重新连接，不自动降级为浏览器模拟。
- Tool 权限或副作用不符合只读策略：拒绝执行并记录审计原因。
- API 调用失败：保存失败证据，但不把失败操作训练成成功样例。

## 7. 验收标准

必须完成以下真实 MES 只读测试：

1. 自然语言查询采购申请列表并展示表格；
2. 按请购人查询，确认参数正确绑定且只返回符合条件的记录；
3. 指定分页参数，确认页码和每页条数生效；
4. 从列表选择记录并展示主记录与申请明细；
5. 确认前三种查询复用同一个列表 Tool；
6. 确认整个流程没有新增 Skill；
7. 确认每次调用均生成脱敏执行证据；
8. 确认没有对 MES 产生写操作。

## 8. 后续演进

完成本轮闭环后，再按需要扩展：

1. 采购领域更多只读 Tool；
2. 按业务域建立分层能力索引与 Tool 检索；
3. 自然语言连续追问和详情查询；
4. 用户主动创建和管理自定义 Skill；
5. 智能体在 Tool 不足时建议录制 Skill；
6. 多业务系统和多领域智能体协作。
