# CommandCenter V1 单系统 Skill 闭环设计

状态：已确认并实施

日期：2026-07-28

适用范围：`D:\python\CommandCenter`

本设计取代 `2026-07-28-command-center-v1-minimal-agent-loop-design.md` 中的跨系统样板流程。旧文档保留为设计演进记录，不再作为 V1 的实施依据。

## 1. 目标

V1 只验证一件核心能力：

> 员工在一个业务系统中演示一次简单操作，中控自动学习并发布一个可复用的 API Skill，之后员工可以用自然语言调用该 Skill。

第一版只使用采购系统，不使用办公用品系统，也不验证跨系统数据传递。

## 2. 唯一样板流程

员工演示：

```text
打开采购系统
→ 填写采购申请
→ 提交采购申请
→ 采购系统返回采购单号
→ 结束演示
```

中控学习：

```text
记录页面操作和真实 API 请求
→ 识别“创建采购申请”业务动作
→ 将演示值抽象成物品、数量和采购原因等参数
→ 生成“创建采购申请”候选 Skill
→ 智能体生成并执行无害测试
→ 测试通过后自动发布
```

员工复用：

```text
输入“帮我为行政部采购 10 箱打印纸”
→ 智能体匹配“创建采购申请”Skill
→ 从自然语言提取参数
→ LangGraph 调用采购系统 API Tool
→ 验证采购申请已经创建
→ 返回采购单号
```

## 3. 系统边界

V1 闭环只依赖：

- CommandCenter 中控系统；
- 采购测试系统；
- 采购系统的创建申请 API；
- Playwright 录制页面操作和网络请求；
- LangGraph 编排学习、测试和执行；
- 结构化智能体输出；
- SQLite 保存录制、Skill、测试和执行记录。

办公用品系统可以继续保留在项目中，供原有快速接入功能和未来实验使用，但它不参与 V1 Skill 录制、测试、发布或执行。

## 4. Skill 定义

V1 只需要生成一种 Skill：

```text
名称：创建采购申请
输入：物品名称、数量、采购原因
操作：调用采购系统创建申请 API
输出：采购单号和创建状态
成功条件：采购系统中存在对应采购申请
```

Skill 执行 API，不回放鼠标点击。页面操作只用于帮助中控理解员工演示的业务含义，以及确定本次操作对应哪个允许调用的 API Tool。

## 5. 用户界面

### 演示工作台

- 默认目标为“创建采购申请”；
- 点击开始演示后只打开采购系统；
- 提示员工填写并提交一条采购申请；
- 不再提示切换系统、复制单号或回写单号；
- 结束演示后显示分析、自动测试、发布或需要重新演示的状态。

### 普通任务中心

- 员工输入自然语言采购任务；
- 中控自动匹配已发布 Skill；
- 页面返回执行状态和采购单号；
- 不查询或更新办公用品任务。

## 6. 无害测试

智能体在本地采购测试数据库上生成测试值并测试候选 Skill，至少覆盖：

1. 正常创建采购申请；
2. 使用另一组申请人、物品和数量创建申请；
3. 使用相同幂等键重复调用时不重复创建申请。

全部测试通过才自动发布。测试失败时保存原因，并要求重新演示；V1 不自动修改候选 Skill。

## 7. 明确不做

V1 不做：

- 跨系统操作；
- 采购单号回写；
- 办公用品任务读取或状态更新；
- 多业务对象选择；
- 无 API 系统的浏览器自动化执行；
- 多次演示融合；
- 管理员审核工作流；
- 生产系统接入和权限体系。

这些能力只有在单系统 Skill 闭环稳定后再逐步增加。

## 8. 完成标准

以下流程能够真实跑通时，V1 完成：

1. 员工在采购系统演示提交一条采购申请；
2. 中控记录到对应页面事件和采购 API 请求；
3. 智能体生成“创建采购申请”Skill；
4. 智能体完成正常、参数变化和幂等测试；
5. Skill 自动发布；
6. 员工通过自然语言发起另一条采购申请；
7. 中控调用 Skill，在采购系统中只创建一条申请；
8. 页面返回真实采购单号；
9. 后端测试、前端测试和前端构建通过。
